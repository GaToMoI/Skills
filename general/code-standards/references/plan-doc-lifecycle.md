# 计划文档生命周期细则 (Plan Document Lifecycle)

> 硬规则内联在 [`SKILL.md`](../SKILL.md) 第六节；本文件给模板、状态词口径与判例。

## 1. 适用边界

- **适用**：多阶段 / 多期执行计划——切片计划、里程碑计划、跨会话接续的长计划。
- **不适用**：单次任务的步骤清单。直接做，不建文档、不进索引。

## 2. 计划文档骨架

```markdown
# <主题> 切片计划

> 状态：执行中 ｜ 起于 YYYY-MM-DD ｜ 依据：<ADR / 调研稿链接>

## 目标与验收口径
## 阶段划分
### S1 <阶段名>
- [x] 任务项（2026-10-09）
- [ ] 任务项
## 已知限制 / 待决
```

- 阶段标 `S0 S1 S2…`，便于跨会话精确引用（「S2 待开工」）。
- 任务项须**可判定完成**；「持续优化」类不可收口项不写进清单，写进「已知限制 / 待决」。

## 3. 状态词口径

| 状态 | 含义 |
|:--|:--|
| 待开工 | 已起草，未开始 |
| 执行中 | 至少一个阶段在推进 |
| 待验收 | 实现完成，等用户验收 |
| 已交付 | 验收通过——该计划随即应被删除（收口） |

## 4. 执行中目录 README 结构

置顶一段接续指引（「clear context 后先看这里」：当前主计划 + 卡在哪 + 下一步）→ **计划索引表** → **遗留表**（`L1 / L2 …` 编号，便于对话中直接引用）→ **待讨论区**（指向独立子目录）。

## 5. 实例：GTMIAgent

`docs/todo/`（执行中，下含「未讨论清楚todo/」子目录）+ `docs/plans/`（冻结归档）+ `docs/todo/README.md`（接续指引 + 计划索引 + L1–L3 遗留 + 待讨论区）。

## 6. 与其他纪律的接口

| 内容 | 去处 |
|:--|:--|
| 完成痕迹 | changelog |
| 设计取舍 / 架构决策 | ADR |
| 调试日志 / 一次性脚本 | `.tempcache/` |
| 未讨论清楚的构想 | 执行中目录的「未讨论清楚」子目录 |

## 7. 反面判例

- 计划全项完成却长期留在执行中目录（永不收口，索引读起来失真）。
- 顺手往已冻结的归档目录追加新计划。
- 完成痕迹两处重复记账（计划文档与 changelog 各写一遍）。
- 为一次性子任务建计划文档 + 索引（技能滥用到日常小任务）。
