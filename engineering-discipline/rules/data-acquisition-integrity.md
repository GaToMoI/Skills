# 准则十：数据获取与解析完整性 (Data Acquisition & Parsing Integrity)

## 1. 触发场景
- 抓取网页 / API 中的表格、键值对、定价数据等结构化信息，用于对比、计算或结论输出；
- 从 HTML / JSON / 日志中提取数值并据此下结论时。

## 2. 铁律
1. **结构化数据禁止线性化剥取**：
   - 严禁用 `re.sub('<[^>]+>', ' ', txt)` 之类把 HTML 剥成纯文本后，按文本顺序直接读取数值；
   - 必须保留「值 ↔ 标签」的对应关系（如 `data-model` 对应 `data-value`、表格行列结构、JSON key-value）；
   - 若只能拿到线性文本流，必须明确字段顺序（数值在前还是标签在前），防止整体错位。
2. **多来源第一时间交叉核对**：
   - 同一数据出现多个来源（首页 / 文档 / API 端点）时，立即对比；
   - 若不一致，以官方文档 / 正式 API 为准，并向用户标注差异与原因；
   - 严禁为「自圆其说」而编造来源差异。
3. **异常数字合理性校验（Red Flag）**：
   - 当结果明显夸张（数量级远超同类平台常态、每美元 token 量异常、请求数异常）时，必须停下质疑；
   - 回查原始数据是否读错、单位是否换算错、字段是否错位；
   - 严禁带着「预期它便宜 / 它很好」的先入为主去相信异常数字。
4. **结论可溯源**：
   - 引用数据时必须能指出原始来源（URL / 本地抓取文件）与抓取时间；
   - 用户质疑数据时，优先回查原始抓取文件，而非凭记忆重新编造。

## 3. 复盘案例（2026-08）
- 抓取 OpenCode Go 首页 DeepSeek 额度表时，用正则剥 HTML 成纯文本后按「模型名后面的数字」读取；
  因实际 HTML 顺序是「数值在前、模型名在后」，导致额度整体错位：
  把 MiMo-V2.5 的 30,100 读成 DeepSeek V4 Flash、GPT-5.6 Luna 的 2,050 读成 V4 Pro。
- 正确值（首页与 docs 一致）：DeepSeek V4 Flash = 7,600 / V4 Pro = 1,050 请求/5小时。
- 教训：结构化解析 + 交叉核对 + 异常值校验，三者缺一不可。
